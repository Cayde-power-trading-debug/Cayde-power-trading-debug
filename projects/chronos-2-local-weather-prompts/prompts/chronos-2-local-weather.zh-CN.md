# Chronos-2 本地下载、GPU 部署与地理天气自动预测系统：开发提示词

使用方法：将下面“提示词正文”整体交给具备本地文件、终端和开发能力的编程助手执行。本文交付的是部署提示词，未实际安装模型或运行 GPU 测试。

资料核对日期：2026-09-18。涉及版本和 API 时，执行助手应再次检查官方资料，并锁定实际验证通过的版本。

## 提示词正文

你是一名熟悉 Python、PyTorch CUDA、时间序列预测及前后端开发的工程师。请在我的本地电脑上部署 Amazon Chronos-2，并开发一个可实际使用的中文 HTML 预测系统。请完成代码、依赖安装、模型下载、联调和验证，不要只给方案或伪代码。若当前环境没有执行权限，请提供完整项目与准确的启动步骤，明确哪些验证未执行。

### 1. 目标与范围

实现以下完整流程：

1. 浏览器打开本地 HTML 页面。
2. 上传历史数据，自动识别文件、工作表、字段类型、时间列、预测目标候选列、序列标识及辅助变量。
3. 页面显示识别结果，允许我修正字段映射、选择目标和数据频率。
4. 自定义城市、站点或地理位置范围，自动获取对应历史天气与未来天气预报，转换为模型辅助变量；也可上传辅助变量文件。
5. 我选择预测开始日期、结束日期；小时或分钟数据支持具体时刻。
6. Python 后端调用本地 Chronos-2，用 NVIDIA GPU 的 CUDA 执行模型推理。
7. 页面显示历史曲线、预测曲线、分位数区间和结果表，允许下载 CSV、Excel。

采用本地零样本预测作为第一版，不默认增加微调、云端推理、登录系统或复杂数据库。上传的业务数据和模型推理留在本机；模型下载和实时天气获取需要联网。天气服务只接收必要的地理位置、时间范围和天气变量请求，不上传我的业务目标值或整份业务文件。

### 2. 先检测环境，必要时询问我

开始安装前，尽量通过只读命令自动检测：操作系统、Python 与现有虚拟环境、NVIDIA 显卡型号、显存、驱动版本、可用磁盘空间，以及当前 PyTorch 的版本和 CUDA 可用性。不要把执行助手运行所在的远程环境误当成我的目标电脑。

若无法检测目标机器，先问我：

> 你准备部署的电脑是什么操作系统（Windows、Linux 或其他）？NVIDIA 显卡型号和显存大小是多少？是否已有 Python/Conda 环境？如果不清楚，请提供适用于该系统的检测命令并解释如何查看结果。

将检测结果写入环境报告，再选择兼容的安装方案。Windows 优先采用原生 Python 虚拟环境；只有存在已确认的兼容问题时才考虑 WSL2，并解释原因。不要擅自覆盖已有环境、修改系统驱动或删除用户文件。

如果没有可用 NVIDIA CUDA GPU，明确说明 GPU 部分尚未满足要求，提供修复路径；CPU 只能作为页面中明确标识的可选模式，不能静默回退并宣称 CUDA 部署成功。

### 3. 官方来源与版本核验

请优先核对下列官方来源：

- 仓库：https://github.com/amazon-science/chronos-forecasting
- 模型：https://huggingface.co/amazon/chronos-2
- 推理实现：https://github.com/amazon-science/chronos-forecasting/blob/main/src/chronos/chronos2/pipeline.py
- 示例：https://github.com/amazon-science/chronos-forecasting/blob/main/notebooks/chronos-2-quickstart.ipynb
- PyTorch 安装：https://pytorch.org/get-started/locally/

必须使用 `amazon/chronos-2`，不要误换成 Chronos-T5、Chronos-Bolt 或其他模型。核实 `chronos-forecasting`、PyTorch、Transformers 等依赖的兼容关系，以及 `Chronos2Pipeline` 和 `predict_df` 的实际参数签名。使用官方支持的安装方式；验证后锁定依赖版本，并记录模型 revision，保证可复现。

不要直接照抄过期 CUDA wheel 安装命令。依据操作系统、驱动和官方支持矩阵选择 GPU 版 PyTorch；区分驱动支持的 CUDA 版本、PyTorch 自带 CUDA 运行时与系统 CUDA Toolkit，不把它们误认为必须完全相同。

### 4. 项目架构

默认采用 Python + FastAPI 后端、原生 HTML/CSS/JavaScript 前端，通过同一后端提供页面和 API。图表库保存在本地，避免页面依赖外部 CDN。只绑定 `127.0.0.1`，提供明确的本地访问地址。

将代码按文件解析、字段识别、数据校验、时间范围处理、模型推理、任务管理和结果导出拆分，避免所有逻辑塞入一个文件。提供配置文件或 `.env.example`，至少包括模型目录、GPU 编号、批大小、历史窗口、上传大小限制、结果目录及服务端口。

模型在后端进程中加载一次并复用；单 GPU 默认一次执行一个推理任务，其他任务排队。采用后台任务执行器，避免阻塞 API；默认单服务进程，防止多 worker 重复加载模型耗尽显存。

模型和依赖下载完成后，支持从明确的本地模型目录离线启动。离线缺少文件时给出诊断，不能悄悄联网或换模型。

#### 4.1 必须实际下载模型权重到本地

请帮我下载可完整加载的 `amazon/chronos-2` 模型，不要只克隆 GitHub 源码仓库、创建空目录或留下模型链接。

- 默认下载到项目的 `models/chronos-2/`，允许配置其他磁盘目录；下载前检查可用空间。
- 使用 Hugging Face 官方 `huggingface_hub.snapshot_download` 或当前官方 CLI，锁定并记录实际 revision。核对当前版本参数后实现下载脚本，支持失败重试及利用已下载文件继续下载，避免每次启动重复下载。
- 下载权重、配置及当前 pipeline 加载所需的全部文件；检查文件非空且并非 Git LFS 指针，保存文件清单、大小和完整性验证记录。不要猜测固定文件名后漏掉必要文件。
- 页面或安装日志显示下载状态、目标路径、失败原因；网络不可达时提供可执行的重试或手动导入方案，不能声称下载完成。
- 后端从本地路径加载，采用当前版本支持的离线设置禁止加载时自动下载；在断网环境完成实际加载和预测验收。
- 将“源码”“Python 依赖”“模型权重”分别说明，最终报告给出模型绝对路径、revision、下载体积和加载结果。

天气模块允许联网更新；离线模式只能使用已缓存或用户导入的天气数据，缺少预测区间天气时明确提示。

### 5. CUDA 推理实现和证据

请编写真实 GPU 推理代码，而不只是打印“GPU 已启用”。

- 检查 `torch.cuda.is_available()`，记录 GPU 名称、设备编号、显存、PyTorch 版本及其 CUDA 运行时。
- 显式指定 CUDA 设备；以所安装版本支持的方式加载 `Chronos2Pipeline`，并验证实际模型参数设备。
- 推理使用评估模式和 `torch.inference_mode()`；数据搬运遵循官方 pipeline 的实现，不要求 pandas DataFrame 本身位于 GPU。
- 先以兼容性优先的数值精度完成验证，再按硬件和模型支持情况选择混合精度，不盲目强制 FP16/BF16。
- 记录推理耗时和峰值显存；测量 GPU 耗时前后进行必要的 CUDA 同步。
- 显存不足时优先减小批大小；如需缩短历史窗口，必须在页面明确展示实际使用范围。失败后释放任务资源，提供可读错误，禁止无提示切换 CPU。
- 附带独立 GPU 冒烟测试：真实加载模型、运行一段示例历史数据、输出有限且非空的预测值，并断言模型在 CUDA 上。条件允许时使用 profiler 确认模型前向包含 CUDA 运算。

官方接口方向为：`from chronos import Chronos2Pipeline`，加载时指定 `device_map="cuda"`，使用 `predict_df` 传入历史 DataFrame、预测步数、字段名称和分位数。请基于实际安装版本实现完整函数和异常处理，不混用旧版采样接口。

### 6. 上传文件和字段识别

第一版支持 CSV 与 XLSX。XLSX 可选择工作表；CSV 处理 UTF-8、UTF-8 BOM 和常见中文编码，遇到歧义时允许选择编码。显示前若干行预览、总行数、列名、空值比例与数据类型。

采用列名线索、样本值、时间解析成功率与数值比例共同识别，给出候选及原因，不把猜测当成确定结果。

需要识别并允许手动设置：

| 字段角色 | 识别示例与要求 |
| --- | --- |
| 时间列 | 日期、时间、timestamp、datetime；支持用户明确指定日期列与时刻列合并 |
| 序列 ID | 站点、设备、区域、item_id；无此列时建立单序列 ID |
| 预测目标 | 负荷、价格、销量、target 等数值列；多个候选时让我选择 |
| 历史辅助变量 | 历史温度、历史运行状态等，只在历史区间提供 |
| 未来已知辅助变量 | 日历、排程及用户提供的预测期特征，需要覆盖完整推理区间 |
| 忽略列 | 备注、流水编号及与预测无关的字段，不自动全部加入模型 |

“自动识别”只代表数据结构与角色建议，不承诺自动理解所有业务语义。不调用外部大模型解析上传数据。

默认支持长表；对“时间列 + 多个数值列”的宽表，让我选择是多个独立序列，还是同一对象的多个预测目标，明确转换规则。不同序列分别校验时间频率和历史截止时间，再按兼容条件分组预测。

至少检查：日期解析失败、重复时间戳、时间乱序、缺失时间点、目标非数值、无穷值、全空列和历史样本不足。排序可自动完成；重复值聚合、插补和重采样必须展示规则，不能静默处理。报错指出工作表、字段及原始行号。

ID 按字符串处理，保留前导零。不要默认把缺失目标值补成零。重采样时明确求和、均值或其他聚合方式，避免改变业务含义。

### 7. 预测日期范围：必须准确实现

模型按连续时间步预测，前端日期范围必须转成正确的预测步数。

1. 对每个序列，确定真实历史截止时间 `t_last` 和已确认的时间频率 `freq`。
2. 由 `t_last` 的下一有效时间点连续生成到用户结束时间的完整时间网格。
3. 完整网格的长度才是传给模型的 `prediction_length`。
4. 模型输出按真实时间戳对齐，再截取用户开始时间至结束时间范围内的结果。
5. 不能只按“结束减开始”计算步数；预测开始日期晚于历史末尾时，中间缺口也必须预测。

示例：日频历史截至 2026-09-10，我选择 2026-09-15 至 2026-09-20。应连续预测 9 月 11—20 日共 10 步，再返回 15—20 日共 6 行。

时间处理要求：

- 支持 15 分钟、30 分钟、小时、日、周和月等经过校验的规则频率；自动推断失败时让我选择。
- 用日历 offset 生成月频、周频等网格，不用固定秒数近似月份。
- 明确时区，内部处理和浏览器展示保持一致，避免浏览器 UTC 转换导致日期偏移。
- 日期模式中，结束日期包含当天所有有效采样点；日期时间模式按选定网格点含首含尾。不对齐的时刻应提示修正，不能偷偷取整。
- 默认“未来预测”要求开始时间晚于该序列历史截止时间。历史范围通过独立“回测模式”处理，或明确拒绝并解释，不能混入实际值伪装预测。
- 若实现回测，输入截断在预测起点之前，起点及之后的实际目标只用于评估；插补和特征处理也不能访问未来目标。
- 不同序列历史截止时间不同时，分别计算总步数，并逐一显示可预测范围；不能用最长序列的截止时间替代所有序列。

读取实际模型配置和当前接口支持范围，设置可解释的预测跨度限制。模型卡列出的上下文和预测长度不能当作任意跨度都可靠的保证。第一版默认拒绝超过已验证范围的请求，并显示最大结束日期；若提供长跨度模式，必须先验证官方实现，明确其策略、计算成本和预测质量限制。不能偷偷截断输出、重复拼接同一段结果，或把超长预测直接说成绝对不支持。

### 8. 辅助变量与防止信息泄漏

区分预测目标、历史辅助变量和未来已知辅助变量，页面明确列出进入模型的字段。

未来辅助变量必须按序列 ID 与时间戳对齐，并覆盖从历史下一时间点到预测结束的整个区间，包括未展示的中间缺口。缺失时列出缺少的字段和时间范围；只有经过用户明确选择，才能移除该辅助变量或采用有记录的替代方案。

日历特征可由程序生成，但历史和未来必须采用一致定义。未来实际温度、实际价格等未知数据不能自动当成可用特征；用户提供的天气预报可作为未来输入，并标注来源。未来文件中的目标真实值不得进入预测输入。

保留官方输入校验。不要通过关闭时间戳校验掩盖 future_df 对齐错误。实现官方输出到统一结果结构的适配层，并通过实际输出确认列名、目标名称及分位数含义。

#### 8.1 自定义地理范围与天气自动获取

请实现完整天气获取模块。“爬取天气”优先使用数据提供方公开、可用的结构化 API；只有没有适用 API 且允许访问时才解析公开网页。Chronos-2 本身不会联网找天气，必须由本项目后端完成下载、清洗、匹配和特征构造。

前端支持以下地理输入方式：

1. 输入省、市、区县名称，可添加多个地点；同名地点显示上级行政区和坐标供选择，不自动选错。
2. 输入经纬度，或批量上传包含序列 ID、地点名称、纬度、经度的 CSV/XLSX。
3. 输入经纬度矩形范围，或上传 WGS84 GeoJSON Polygon/MultiPolygon；按可配置网格或已选站点采样，过滤范围外的点，并显示采样数量。地图框选可作为增强项，数值和文件输入必须可独立使用。
4. 选择行政区域时使用有来源的边界数据生成代表点或匹配站点。若仅用行政中心点，必须明确标为“中心点近似”，不能称为全区域天气。

对坐标检查经纬度顺序、有效范围和坐标系；如使用国内地图坐标，明确转换规则，不能将 GCJ-02/BD-09 直接当作 WGS84 查询。限制最大采样点数，避免大范围请求无上限。

建立显式的“业务序列 ID → 地点/范围 → 站点或网格点”映射。支持多个业务序列共用一个地点；一个业务序列关联多个地点时，支持逐地点保留特征，或按用户选择进行区域聚合。

默认可采用等权区域汇总，但必须标明；支持用户提供人口、负荷或装机容量等权重并校验。不要擅自把等权均值称为负荷加权，也不要假设一个城市的气温代表全省。记录匹配距离、原始点位和区域聚合方式。

#### 8.2 天气来源与字段选择

实现可替换的天气 provider 层，先核查候选来源的覆盖区域、历史范围、发布时间、时间分辨率、字段、预报跨度、调用限额、许可与认证方式，再接入并记录实际使用来源。

可优先验证 Open-Meteo 的历史天气、天气预报与地理编码接口；若目标地区访问或字段不满足需求，提供其他可核实的气象数据源适配方案。不要把候选接口写成已测试可用，也不要假设所有免费服务都允许所有用途。需要 API Key 时放在本地配置中，不写入前端或日志。

网页天气文字必须转换成经过验证的结构化字段；没有数值或明确编码的内容不直接送入模型。明确区分地面站观测、再分析数据和数值预报，不能把再分析称为站点实测。

按业务场景建议并允许选择以下候选特征，以数据源实际可用为准：

| 天气特征 | 示例用途和处理要求 |
| --- | --- |
| 气温、日最高/最低温、体感温度 | 负荷等任务的候选辅助变量，保留单位 |
| 相对湿度、露点 | 与温度组合使用，避免无意义重复特征 |
| 降水量、降雪量 | 区分累积量、强度和概率；聚合方式不同 |
| 风速、风向、阵风 | 保留观测/预报高度；风向采用一致的周期编码或矢量处理 |
| 总云量、短波辐射、日照 | 按源数据可用性接入，区分能量累积与平均功率 |
| 气压 | 区分海平面气压和地面气压 |

不要宣称 Chronos-2 固定要求以上全部字段，也不要承诺加入天气一定提高精度。默认采用少量相关、历史与未来均可用的特征；记录未选用或不可用的字段及原因。若实现特征筛选，只利用预测起点之前的数据。

#### 8.3 天气时间范围、更新和质量处理

- 历史天气覆盖模型实际使用的历史窗口；未来天气覆盖完整推理网格，包含历史末尾到用户所选开始日期之间的缺口。
- 历史目标截止时间早于当前时间时，明确预测是“基于当前可用信息”还是“模拟历史发布时点”；两种模式的数据可用性规则不同。
- 根据数据源实际返回检查时间覆盖、更新延迟与预报结束时间。展示“模型跨度上限”和“天气可覆盖上限”，带天气预测默认取可满足条件的范围，不能假定天气预报覆盖任意未来日期。
- 超出天气预报期时，默认阻止该配置运行，并允许我明确选择缩短范围、补充自有未来天气文件，或移除相关未来天气变量。不得静默复制最后一天、虚构长期天气或把气候平均值冒充预报。
- 历史归档与近期天气之间的缺口必须逐点检查。若拼接不同来源，记录来源切换、单位、模型和分辨率差异，不留空后默默补零。
- 统一时区、单位和时间标签语义。例如降水对应前一小时累计还是当前小时，必须核对并正确对齐。
- 温度等状态量与降水等累计量采用不同的重采样规则。小时数据转 15 分钟时明确标为插值/分配结果，不声称是原生 15 分钟观测；降水分配需保持累计总量，风向不能直接做普通角度平均。
- 缺失、异常及插补结果均有质量标记；不进行无记录的补零、外推或裁剪。保留原始响应和处理后数据以便追溯。
- 实现缓存、超时、限速、退避重试、分批下载和增量更新；缓存键包含地点、来源、变量、日期及可用的预报版本。预报缓存有明确时效，不能把过期结果当作最新结果。
- 获取失败时保留失败地点和日期范围，提供重试或人工导入入口；不使用其他地点天气偷偷替代。

对于回测，必须使用在对应预测发布时点已经可获得的天气信息。优先使用具有发布时间的历史预报归档；只有历史实况/再分析时，不能将其作为“当时已知的未来天气”来证明真实预测效果。可单独做理想天气条件实验，但必须标明该实验含事后天气信息。历史上下文天气也要考虑源数据发布时间和延迟。

#### 8.4 自动接入 Chronos-2 的数据流

实现并验证以下流水线：

`业务数据上传 → 字段确认 → 地理映射 → 天气下载/读取缓存 → 单位与时间统一 → 空间聚合 → 按序列和时间合并 → 完整性校验 → context_df/future_df → 本地 CUDA 推理`

历史天气加入 `context_df`；具有完整未来预报的同名特征同时加入 `future_df`。仅历史可用的天气作为历史辅助变量，不伪造未来列。历史与未来的字段含义、名称、单位、编码和空间聚合方式保持一致。

天气原始表至少保存 `location_id`、时间戳、变量值、单位、来源、数据类型及抓取时间。来源提供时另存预报发布时间/起报时间；没有时记为未知，不能用抓取时间冒充发布时间。元数据留在旁表，不把下载时间、来源字符串等无意加入模型特征。

为避免列名冲突，天气特征采用一致前缀，例如 `weather_temperature_2m`。多个地点分别作为特征时增加稳定地点标识。业务文件已有同名天气字段时，让用户选择优先来源并保存配置。

合并后检查 `(序列 ID, 时间戳)` 唯一性和预期行数，防止多地点连接导致笛卡尔积。保存并允许下载本次实际传入模型的历史与未来特征表、字段清单、缺失率、天气原始数据和处理记录。

我确认地理映射与天气配置后，点击一次“获取天气并预测”，系统自动完成全流程，无需手动复制天气到 Excel。天气完整性不满足时停止任务并展示具体缺项；正常情况下自动进入模型推理。

### 9. HTML 页面交互

页面用中文，适配常见桌面分辨率，按照“上传 → 检查字段 → 设置地理范围与天气 → 设置日期 → 获取天气并预测 → 查看和导出”组织。

必须包含：

- 历史数据与未来辅助变量上传区域、工作表选择、示例文件下载。
- 字段映射表、数据预览、校验结果及手动修正入口。
- 城市/坐标/地理范围输入、序列与地点映射、天气变量选择和区域权重设置。
- 天气状态面板：来源、覆盖日期、预报更新信息、原生分辨率、缺失率、缓存状态；支持预览和导出。
- “获取天气并预测”按钮及下载、清洗、对齐等阶段状态；模型未下载时显示下载入口和进度。
- 序列和预测目标选择、频率、日期或日期时间选择器。
- 预测前显示历史截止时间、完整推理步数、所选区间输出行数。
- 环境状态区：模型是否就绪、实际设备、GPU 名称及模型版本。
- 任务状态：排队、加载、预处理、预测、完成或失败；没有可靠进度信息时使用阶段状态，不编造百分比。
- 历史和预测曲线、预测分位数区间、图例、悬停数值及结果表。
- 序列/目标切换、分页或虚拟滚动、CSV 与 XLSX 导出按钮。

默认展示 P10、P50、P90。P50 标为“中位数预测”，P10—P90 标为“预测分位数区间”，不要叫成均值的置信区间，不承诺实际覆盖率必为 80%。

禁用重复提交，失败时保留已选择的数据映射和日期。错误信息应让普通用户知道如何修复。

### 10. API、任务与结果约定

设计并实现以下职责对应的接口，可合理调整路径：

- `GET /api/health`：服务与模型状态。
- `GET /api/environment`：设备及依赖摘要。
- `POST /api/models/download`：创建模型下载任务，复用任务状态查询接口。
- `POST /api/locations/resolve`：解析地名、坐标和范围，返回候选地点及采样点。
- `POST /api/weather/fetch`：按照地理映射、时间和字段创建天气获取任务。
- `GET /api/weather/{id}`：返回天气覆盖、质量和来源信息，提供原始及处理后数据下载。
- `POST /api/datasets`：上传、解析并返回 dataset_id、工作表与字段候选。
- `POST /api/datasets/{id}/validate`：校验映射、频率和清洗设置。
- `POST /api/forecasts`：创建预测任务，返回 job_id。
- `GET /api/jobs/{id}`：查询任务状态与可读错误。
- `GET /api/jobs/{id}/results`：查询结果。
- `GET /api/jobs/{id}/export?format=csv|xlsx`：下载结果。

校验与预测使用同一份确认后的映射和数据版本。预测请求可引用天气数据版本，也可配置自动获取天气后继续推理，任务内部明确串联依赖。每个任务独立保存配置、结果和元数据，避免多个上传互相覆盖；状态应能区分排队、运行、成功、失败和服务重启导致的中断。

统一结果至少包含：序列 ID、目标名称、时间戳、P10、P50、P90。另存原始输入文件摘要、字段映射、时区、频率、完整步数、展示范围、历史窗口、辅助变量、模型 revision、依赖版本、实际推理设备、耗时与显存记录。

导出文件默认仅含用户所选区间，行数应与页面一致。限制上传体积和扩展名，避免文件名造成路径穿越；导出文本字段防止被 Excel 当成公式执行。

### 11. 示例与验收

提供可下载的示例 CSV/XLSX：单序列、多序列、含未来辅助变量，以及故意包含缺失时间点的错误示例。明确示例是合成数据，不将其测试结果表述为业务精度证明。

完成以下必要验证并记录实际结果：

1. 新环境按 README 安装、下载模型并启动页面。
2. 在真实 NVIDIA GPU 上运行 Chronos-2，保存 CUDA 冒烟测试日志；没有 GPU 时标记未验证，不用 mock 冒充。
3. CSV/XLSX 上传、工作表选择、字段识别及手动修正可用。
4. 日期间隔示例返回正确的 6 行，内部预测确实为 10 步。
5. 15 分钟数据单日范围返回 96 个点；测试以无夏令时切换的时区和日期为准。
6. 月频日期、不同序列截止时间及时间网格不对齐得到正确处理。
7. 多目标结果不串列，未来辅助变量缺失或时间不匹配会报错。
8. 如实现回测，验证预测输入不含测试期真实目标；报告 MAE、RMSE，并与适用的朴素基线比较，不预设模型一定更优。
9. 页面图表、结果表、CSV 和 XLSX 的数值、时间范围与行数一致。
10. CUDA 不可用、显存不足、模型文件缺失及非法上传时，能给出可执行的错误提示。
11. 完成模型和所需天气下载后断网启动并预测，确认前端静态资源、模型和天气缓存均从本地加载；断网不能获取新的天气时正确提示。
12. 实际下载完整模型到指定目录，记录 revision、文件清单和离线加载结果。
13. 多城市、同名城市、坐标批量输入和区域采样正确；序列地点映射不串行，空间聚合可复现。
14. 对至少一个真实地点完成天气接口联网集成测试，确认历史与未来覆盖，并生成可检查的模型输入；网络失败时明确标记该测试未通过。
15. 验证天气超出预报期、近期归档缺口、API 限流/失败、缓存过期和字段缺失时的处理。
16. 验证单位、时区、小时转 15 分钟、降水总量守恒及多地点合并后的行数；核对天气列确实传入模型，而不是只在网页展示。
17. 如有回测，验证天气发布时间约束；无法证明历史可用性的结果不得标成无泄漏回测。

单元测试重点覆盖时间范围、字段映射、数据对齐和防泄漏规则；真实模型推理采用集成冒烟测试。明确区分自动化测试、人工页面验证和尚未执行的检查。
